# فحص نقل الإدارة للموبايل — 2026-08-28

## التغييرات

- لوحة إدارة React Native أصلية داخل frontend/src/admin حسب دور الحساب من السيرفر.
- إزالة تقديم موقع /admin/ وأوامر موقع الإدارة من الجذر. مجلد admin-dashboard القديم غير مستخدم؛ تعذر حذفه بسبب سياسة أداة التنفيذ.
- إعادة نموذج الدفع السابق مع بيانات اختبار فقط، ومنع حفظ/إرسال البطاقة وCVV.
- توصيل شاشات الطالب بالسيرفر بدل الخلط بين بيانات العرض المحلي والحساب المسجل.
- عزل بيانات العرض المحلي وإلغاء أثر استجابات جلسة قديمة بعد الخروج/تبديل الحساب.
- تشغيل مرتبط بالتسجيل والاشتراك ونسخة المنهج، وتسلسل أحداث قابل لإعادة المحاولة دون اختراع إكمال محلي.

## نتائج مؤكدة

- اختبارات الموبايل: 46 ناجحة، بما فيها بوابة الأدمن، الطالب والتسجيل، الدفع الوهمي، سباقات تحديث الجلسة والخروج، وإعادة أحداث الفيديو. أضيف فحص وجهة زر Go to Courses بعد الدفع، وفحص إعادة الفيديو بعد انتهائه أو إعادة فتح درس وصل إلى نهايته.
- اختبارات السيرفر: 28 ناجحة، مع HTTP فعلي والتحقق من schemas.
- المسار القديم /admin/ يعيد 404 في اختبار السيرفر.
- بناء TypeScript للسيرفر نجح؛ العقود تغطي 78/78 عملية HTTP.
- فحص TypeScript للموبايل نجح. Lint: صفر أخطاء و17 تحذير أسلوب/تنسيق.
- Android assembleDebug x86_64 نجح (247 مهمة)، وثُبت APK الجديد على المحاكي بنجاح.
- فحص HTTP على السيرفر الجاري: 7 مسارات للأدمن و11 للطالب أعادت 200، مع خروج حسابي الفحص بعد الانتهاء.
- فحص فعلي على محاكي Android: تسجيل دخول الأدمن، لوحة الإحصائيات، قائمة الدورات ومحرر الدورة، سجل الدفعات والخروج. تسجيل دخول الطالب فتح بياناته من السيرفر.
- فحص الدفع من شاشة الطالب الأصلية: تعبئة بيانات الاختبار، نجاح الاشتراك الوهمي، ظهور رسالة النجاح كاملة، ثم فتح My courses بزر Go to Courses. تم التحقق عبر API من اشتراك نشط واحد وعملية دفع واحدة رغم إعادة الدفع لنفس الخطة.
- التسجيل بدورة Advanced Prototyping وتشغيل HLS من السيرفر نجحا. أكد API مشاهدة الدرس الثاني كاملًا (18 ثانية) مع completed=true، وظهرت علامة الإكمال والتقدم نفسه على الموبايل.
- كشف الفحص الفعلي أن Resume عند نهاية الفيديو لا يعيد التشغيل. أصبح الزر Replay ويعيد الموضع إلى الصفر ويرسل حدث seek؛ إعادة فتح درس عند نهايته تبدأ من الصفر أيضًا. لا تمنح إعادة التشغيل إكمالًا محليًا.
- بعد الإصلاح، أُعيد تشغيل الدرس الأول من نهايته على المحاكي واكتملت الدورة إلى 100%. أكد API مشاهدة 18 ثانية لكل درس، completed=true لكليهما، وإصدار شهادة بحالة issued. جُرّب زر Replay نفسه وظهر الفيديو من بدايته في حالة تشغيل.

## حدود الفحص

هذه مراجعة واختبارات للتدفقات المتاحة، وليست ضمانًا بعدم وجود أي خطأ في كل ظرف.
لم يُختبر iOS على Windows. خدمات Google/Apple login والبريد الخارجي تحتاج إعدادًا مستقلًا؛ الدفع الحقيقي معطل عمدًا.
لم تُنفذ كل عمليات CRUD ورفع الملفات يدويًا على الجهاز؛ فُحصت العقود واختبارات الرفع وبناء المكتبات الأصلية. الكتالوج المحلي يحتوي دروسًا تجريبية قصيرة وليس محتوى دورات إنتاجية. لم يُجر فحص بصري لكل شاشة على كل قياس شاشة، ولا يُدّعى تطابق كامل لتصميم شاشات البيانات الجديدة مع Figma.
ظهر انقطاع اتصال مؤقت على المحاكي في نهاية الفحص شمل Metro وAPI؛ بقيت العمليتان تعملان، ونجح طلب HTTP من المضيف، ثم عادت صفحة My courses وجلبت تقدم 100% من السيرفر. لم يُثبت سبب الانقطاع، ولم يُخفَ خطأ الشبكة أو يُستبدل بنجاح محلي.

## إصلاح تشغيل التطوير على Windows
ظهر خطأ OkHttp عند تحميل استجابة Metro multipart، وكان يعلق شاشة البدء. أضيف middleware في metro.config.js لإرسال ملفات .bundle كاستجابة JavaScript عادية على Windows فقط. اختُبر أنه يغيّر طلب bundle ولا يغيّر /status (فحصان ناجحان)، وأعيد تشغيل Metro وظهرت شاشة تسجيل الدخول الأصلية على المحاكي. هذا الإعداد خاص بخادم التطوير ولا يغير API أو نسخة الإنتاج.
