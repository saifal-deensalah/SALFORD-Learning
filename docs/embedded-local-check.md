# نتيجة تفعيل قاعدة البيانات المحلية — 2026-08-28

## النتيجة

الإعداد الفعلي أصبح **محليًا بالكامل من جهة السيرفر وقاعدة البيانات والملفات**: `DB_MODE=embedded` عبر PGlite، و`HOST=127.0.0.1` على المنفذ3000. لا يلزم PostgreSQL أو Docker أو Redis منفصل، ولا مفاتيح Supabase. أوقفت عمليات التحقق، وتأكدت أن منافذ3000 و5173 و8082 مغلقة وأن قفل القاعدة أُزيل بالإغلاق الطبيعي، دون حذف بيانات.

لم يُجرَ اتصال جديد بـSupabase، ولم تُنفّذ عليها migrations أو تعديلات أو عمليات نقل. أُوقف السيرفر السابق قبل التهيئة.

## الإعدادات والبيانات المحفوظة

- الأولوية المؤكدة من الكود: **متغيرات العملية > `backendCSC/.env` > `backendCSC/.env.local`**. لا يتم استبدال قيمة موجودة.
- `.env` يحتوي الإعداد المحلي الفعلي، و`.env.local` أصبح تعليقات فقط. لا توجد فيهما بيانات اتصال سحابي محمّلة. المنافذ العامة ما زالت من `frontend/src/services/local-config.json`.
- قاعدة البيانات الحالية: `C:\Projects\CSCApp\backendCSC\.local\local-app\postgres`، schema `public`. اسم قاعدة PGlite الداخلي هو `template1`.
- `DATA_DIR` هو `C:\Projects\CSCApp\backendCSC\.local\local-app`. يحتوي أيضًا السر الدائم وحسابات demo والوسائط؛ الرسائل المحلية تُحفظ داخله عند إنشائها. بيانات الحسابات الخاصة في `demo-accounts.json` ولا تُطبع في التقارير.
- الإعداد السابق نُسخ مع شهادة TLS إلى `C:\Users\salma\.cscapp-private\supabase-config-20260828-160946`، خارج المشروع وGit. طابقت النسخة بايتًا ببايت؛ صلاحيات NTFS مقتصرة على حساب Windows الحالي وSYSTEM. النسخة محمية بالصلاحيات، وليست أرشيفًا مشفرًا بكلمة مرور.
- القاعدة القديمة `backendCSC/.local/postgres` بقيت دون تغيير: طابقت hashes **1160 ملفًا** قبل العمل وبعده. لم تُنقل بياناتها إلى المجلد الجديد، ولم تُحذف ملفات المستخدم.

## التهيئة

اختير مجلد جديد لحماية القاعدة المحلية القديمة. `createRuntime` أنشأ PGlite وطبق الملفات الخمسة الموجودة في `backendCSC/database` على القاعدة الجديدة فقط. ثم استخدمت `seed` الموجودة لإضافة حسابي demo و7دورات و14درسًا، باستخدام الصور والفيديو المرفقين بالمشروع. لا توجد بيانات مستوردة من Supabase.

التشغيل العادي يفتح نفس المجلد ولا يعيد seed. لا تحتاج إعادة التهيئة. لا تفتح API وseed/migrate/worker منفصلًا على نفس قاعدة PGlite في الوقت نفسه. احتفظ بالمجلد والسر؛ لا تحذف البيانات أو ملفات القفل كحل تلقائي للأخطاء.

## الملفات المتأثرة وحدود التحقق

تغيرت `.env` و`.env.local` و`.env.example` في backendCSC، وفحص `scripts/smoke.mjs` ليعمل محليًا ويرفض السحابة، ومعالجة إعدادات الهوية في `src/auth.ts` واختبارها في `test/api.test.ts`. حُدّث README وأدلة التشغيل وAPI ومسارات بيانات الحسابات والبريد، ووُسم دليل Supabase السابق كمرجع غير مفعّل. لم تتغير عناوين الواجهة أو شاشاتها أو جداول Supabase أو سياساتها.

هذه الجولة تثبت الربط المحلي والتهيئة وAPI، وليست إعادة اختبار تفاعلي لكل شاشة Android أو iOS أو اختبارًا مع تعطيل شبكة الجهاز بالكامل. الإنترنت مطلوب لتنزيل التبعيات وأدوات البناء غير المخزنة أول مرة. ملفات demo وقاعدة البيانات محلية؛ يلزم تشغيل الكمبيوتر والـbackend للوصول إليها من الهاتف. البريد المحلي لا يصل إلى صندوق بريد خارجي، والدفع تجريبي فقط، وGoogle/Apple وPush غير مفعّلة.

التشغيل جاهز وفق [README](../README.md) و[دليل التشغيل](local-run.md). سجّل خروجًا من جلسات القاعدة السابقة واستعمل الحسابات المحلية الجديدة؛ حسابات وتقدم Supabase لم تُنقل.
